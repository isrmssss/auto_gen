# investigate — исследование перед гипотезами

Сюда агент складывает **краткие разборы проблемы**, **до** того как писать файлы в `future/`. Цель: не генерировать гипотезы «от балды», а привязать очередь к наблюдаемым разрывам метрик.

## Когда писать

| Момент | Действие |
|--------|----------|
| **После прогона цикла** | Обновить или создать brief: что осталось сломанным у champion, что починилось у treatment, что не сработало |
| **Перед заполнением `future/`** | Прочитать активные brief; каждая новая гипотеза ссылается на brief + вопрос |
| **При пустой очереди** | Сначала brief (разбор champion / control), потом гипотезы |

Один brief может породить **несколько** гипотез разных типов (refine/pivot/explore), но каждая гипотеза обязана ссылаться на конкретный вопрос из brief.

## Research pack (артефакты, не конкретные скрипты)

Инструменты считает **целевой проект**. Минимальный набор цифр в brief:

| Бакет | Смысл (относительно labeled ref) |
|-------|----------------------------------|
| **persist** | ошибка у baseline и у treatment |
| **fixed** | ошибка у baseline, у treatment нет |
| **regress** | у baseline ок, у treatment ошибка |

Плюс топ срезов по `slice_dims` из [`METRICS.md`](../METRICS.md). Сравнение — к `baselines.champion` (и control при наличии).

## Шаблон brief (`NNN_slug.md`)

```markdown
# NNN — короткий заголовок вопроса

**Дата / split:** <primary_split>
**Опорный run:** <path или id> · arms: baseline → treatment
**Статус:** open | partially_answered | closed

## Вопрос
Один конкретный вопрос (не «улучшить метрику», а «почему N persist в срезе …»).

## Наблюдения
- Цифры: persist / fixed / regress, топ срезов
- Сравнение с champion / последним treatment
- Что уже пробовали (ссылка на past/Hx) и почему не подошло

## Гипотезы-кандидаты (не окончательные)

Краткая таблица для приоритизации. **Кандидат ≠ текст `future/`:** при записи в очередь развернуть Идея/Почему до 3–5 предложений (см. [`../future/README.md`](../future/README.md)).

| # | Тип | Суть (1–2 информативных предложения) | Риск hard-constraint |
|---|-----|--------------------------------------|----------------------|
| 1 | refine | … | … |

## Анти-паттерны
Что **не** стоит пробовать снова (из INDEX / ❌ / banned_lines).

## Следующий шаг
Какой один эксперимент даст максимум информации при минимальном риске регрессии.
```

## Правила

- Brief **не заменяет** отчёт `past/` — только мост к `future/`.
- Не копировать id кейсов в brief для подбора правил; агрегаты по срезам — ок.
- После того как вопрос закрыт экспериментом → `Статус: closed`, ссылка на `past/hxx.md`.
- Активных brief обычно **1–2**; старые closed не удалять (история рассуждений).
